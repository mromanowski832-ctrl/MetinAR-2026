# METINAR-004 — First visible world-map HUD prototype

## Scope

Prototype-only **world map + phone HUD** scene for MetinAR. Original placeholder art only
(no Metin2 assets). No map SDK, backend, login, real inventory/skills/stats, hand tracking,
sword combat, AR fight flow, drops, or monetization.

Branch: `feat/004-world-map-hud`. Scene:
`client/Assets/MetinAR/Scenes/WorldMapPrototype.unity`.

## What you see

- Local meter world anchored at the player's **first valid location fix** (see METINAR-004B): +Z north, +X east.
- Player capsule placeholder driven by `PlayerLocationService` + `MockLocationProvider`.
- One aggressive mob (“Trujący Pająk”) and one stationary NPC.
- Portrait HUD (1080×1920 scaler): portrait/stats, radar placeholder, quest tracker,
  spinning coin + EXP segments, bottom buttons (EQ / Skille / Ustawienia / Postać / Menu (hamburger)).
- Panels: mob info, inventory grid, character, placeholder menus.

## Mock movement (Editor / Development Build)

`EditorMockMovement` (compiled out of release player builds without `DEVELOPMENT_BUILD`):

| Input | Action |
|-------|--------|
| W / ↑ | Move forward (along heading) via `MockProvider.MoveMeters` |
| S / ↓ | Move backward |
| A / ← | Strafe left |
| D / → | Strafe right |
| Q / E | Rotate heading |

Location subsystem is unchanged; `GeoCoordinate` / `GeoMath` were not modified.

## Mob / NPC behaviour

- **Mob:** world name+distance label; click opens `MobInfoPanel`; if aggressive and player
  enters `aggroRangeMeters`, shows “Zostałeś zaatakowany” and logs
  `AR ENCOUNTER REQUESTED` (debounced). Panel button “Wejdź do AR” does the same log/toast.
- **NPC:** distinct color/shape, stationary, no gameplay logic.

  (13.2 m, just outside the 12 m aggro range), NPC at 2.5 m W / 4 m N; larger no-wrap world labels;

- `EditorMockMovement.ApplyMoveInput(Vector2, dt)` / `ApplyTurnInput(float, dt)` are the single

  "Zostałeś zaatakowany" and emits one encounter request (8 s debounce).

### Play Mode smoke test

`com.unity.test-framework` is not in the manifest and the MetinAR scripts have no asmdef, so an


## METINAR-004B — device-ready prototype

### Provider selection

The scene stores `PlayerLocationService.ProviderKind.Auto` (`_providerKind: 0`), no longer a forced
`Mock`. Runtime resolution is unchanged (`PlayerLocationService.ResolveKind`):

| Platform | Provider |
|----------|----------|
| `UNITY_EDITOR` | `MockLocationProvider` (WASD/arrows + Q/E via `EditorMockMovement`) |
| Android / iOS player | `UnityLocationProvider` (foreground GPS only) |
| other platforms | `MockLocationProvider` |

### First-fix origin

- `WorldMapOrigin` has no serialized/default origin. `HasOrigin` is false until `CaptureOrigin`
  runs, which succeeds only once (`OriginCaptured` event).
- `PrototypeWorldPlacement` (on `Systems`, `DefaultExecutionOrder(-100)`) waits for the first valid
  `LocationFix`, captures the origin from that exact coordinate, then sets
  mob = `GeoMath.OffsetMeters(firstFix, 13 N, 2 E)` and NPC = `GeoMath.OffsetMeters(firstFix, 4 N, -2.5 E)`,
  activates them, and sets `IsInitialized` (+ `Initialized` event). It initializes once only and works
  with any provider. No real-world coordinate is hard-coded.
- Mob and NPC are saved **inactive** and only placed/activated after the first fix.
  `WorldMapEntity` has no serialized lat/lon and only positions itself when it has a coordinate and
  `WorldMapOrigin.HasOrigin` is true. `PlayerMapAvatar` no longer captures the origin itself; it
  follows fixes once the shared origin exists.
- In the Editor the mock's first fix is Null Island (0, 0), so player starts at local (0, 0),
  mob ≈ 13.15 m, NPC ≈ 4.72 m away (as accepted in 004A).

## METINAR-004B corrections — foreground GPS permission + lifecycle (PR #11 review 5565064786)

Inherited location-subsystem defects found in review; fixed narrowly in `UnityLocationProvider.cs`,
`PlayerLocationService.cs` and new pure helpers (`DeviceLocationProviderCore`, `IDeviceLocationPlatform`,
`LocationPermissionRequest`, `LocationPermissionLevel`, `ISuspendableLocationProvider`,
`ForegroundLocationLifecycle`). Full flow: `docs/METINAR-003.md` → "Corrected Android permission +
lifecycle flow". `GeoCoordinate.cs` / `GeoMath.cs` unchanged; no visual/UI changes.

- **R1:** one `Permission.RequestUserPermissions([FINE, COARSE])`; callbacks retained until the aggregate
  resolves; first grant (either order) starts `Input.location` once; fine denial never cancels a coarse
  grant; denial final only when neither is granted (incl. dismissal); `Stop()` + late callback never
  starts; re-`Start()` during an open dialog does not prompt twice; init timeout disarmed while the
  decision is pending; coarse reported as `PermissionLevel.Approximate`, not as 5 m accuracy.
- **R2:** `PlayerLocationService.OnApplicationPause` → `ForegroundLocationLifecycle`: pause suspends
  acquisition and invalidates cached fixes; resume restarts only a requested, still-permitted attempt;
  explicit stop / disabled component / denied permission are never restarted; the permission dialog's
  own pause/resume keeps the in-flight request (no re-prompt, no background start); the world origin is
  not reset on resume. No background permission/service, no native iOS plugin.
