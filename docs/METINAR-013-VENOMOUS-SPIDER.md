# METINAR-013 — Venomous Spider (first original production mob)

Status: **review** (issue #24). This is a visual asset only. The live AR placeholder (`Prefabs/ArPrototypeSpider`)
and every gameplay scene are unchanged. Hooking it into ArEncounter is a separate follow-up, after METINAR-007.

## 5. Rig and clips

The bones are `B_Root`, `B_Body`, `B_Abdomen`, `B_Head`, `B_Fang_L/R`, and `B_Leg{L|R}_{01..04}_{Coxa,Upper,Lower}`
(8 legs × 3). In Blender the legs use IK (foot targets and knee poles). Those control bones are not deform bones and
are not exported; the clips are baked per frame.

| Clip | Length | Loop | Notes |
|---|---|---|---|
| Idle | 2.4 s (73 f @ 30 fps) | yes | breathing, abdomen sway, fang twitch, front-leg taps |
| Walk | 1.0 s (31 f) | yes | in place, alternating tetrapod gait, 0.16 m stride → **0.32 m/s** at 1× (scale playback speed to move speed) |
| Attack | 1.2 s (37 f) | no | rears up, then a fang strike; **hit frame 18 (0.57 s)** is the animation-event candidate |
| Hit | 0.4 s (13 f) | no | recoil |
| Death | 2.0 s (61 f) | no | collapses with legs curled; ends on the ground |

When sampled in Unity, every clip binds to all 310 curves with no root curves. The lowest skinned vertex goes no
lower than −6 mm below the ground in any clip (check C17).

## 7. Rebuilding the source

```
blender -b --factory-startup --python art-source/VenomousSpider/spider_build.py -- greybox <out>   # checkpoint render
blender -b --factory-startup --python art-source/VenomousSpider/spider_build.py -- full <out>      # FBX + PNG + renders
```

The build is deterministic: two runs produce identical textures and counts. Copy `<out>/VenomousSpider/{Models,
Animations,Textures}` into the asset folder, then run the Unity builder. The `.meta` files keep their GUIDs.

## 8. Findings and limitations

- **Pipeline fix:** with *Bake Axis Conversion*, Unity maps Blender +Y to +Z regardless of the FBX Forward option.
  The model is authored facing −Y, so the export step turns it 180°. [METINAR-009 §3.1](METINAR-009-ASSET-PIPELINE.md)
  has been corrected to match.
- **Pipeline fix:** rigged FBX files now import with *Preserve Hierarchy* on. Clip files that contain only the
  armature otherwise lose their root node and the clips do not bind. The METINAR-009 postprocessor sets this on
  first import, and the builder re-applies it.
- `AssetPipelineValidator` now measures model size from `mesh.bounds` × transform, because `Renderer.bounds` is not
  reliable on assets that are not in a scene.
- Clips are in-place with no root motion. Gameplay drives position and matches Walk playback speed to movement speed.
- The Animator has no transitions or parameters yet; that is integration work. Animation events (attack hit frame
  18) are not baked in.
- The procedural style is clean and stylised rather than sculpted: there is no high-poly bake, and the normal map
  is derived from a painted height map. That is enough for a 1–3 m AR viewing distance; a hand-sculpted pass can
  replace the textures later without changing the UVs or the rig.
