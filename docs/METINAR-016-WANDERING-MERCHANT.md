## 4. Rig and clips

Bone names equal Unity `HumanBodyBones` names, so the Humanoid avatar maps automatically. The builder additionally maps
the optional bones Chest, Jaw, Left/RightShoulder and Left/RightToes (22 bones mapped). Extra bones: Root, Backpack, Lantern.

| State | Length | Loop | Notes |
|---|---|---|---|
| Idle | 3.0 s | yes | breathing, weight shift, hand on the pack strap |
| Walk | 1.2 s | yes | IK-tracked feet, in place (≈ 0.73 m/s stride) |
| TurnLeft / TurnRight | 1.0 s | no | 90° in place, two steps, root rotation kept |
| Talk | 2.0 s | yes | jaw syllables + gestures |
| Interact | 2.0 s | no | reach forward / hand over |

All clips: Humanoid, Copy From Other Avatar (the model avatar), Optimal compression, root height/XZ baked into the pose.

## 6. Notes and known limitations

- **Per-asset `preserveHierarchy`.** The shared postprocessor on `main` does not set it. Without it, Unity collapses the
  single-root clip FBXs and the copied avatar fails ("Parent for 'Root' differs"). The builder sets it only on this
  NPC's importers; the shared `AssetPostprocessor` and `AssetPipelineRules.cs` are not changed.
- **Validator warning (not an error):** "Pivot is not on the ground: mesh min Y = -0.124 m". The validator on `main`
  reads `Renderer.bounds` of the un-instantiated skinned mesh; the baked mesh in Idle stands at y = 0.000 (check C17).
  PR #30's bounds fix would remove this warning.
- Clip-only FBXs are imported as Humanoid and retargeted. Generic playback of the raw curves is not used.
- Mobile performance on a physical device: UNVERIFIED (no Android build in this issue).
